# Muse 字幕预览与渲染方案说明

本文档旨在说明 `Playground` 模块中字幕渲染的核心逻辑，包括样式处理、多重缩放机制以及如何保证“预览即所得”的一致性。

## 1. 核心设计思想

为了保证在不同尺寸的窗口（预览）和不同分辨率（导出）下，字幕的相对位置和比例完全一致，我们建立了一套基于**参考分辨率 (Reference Resolution)** 的渲染体系。

*   **参考宽度 (`REFERENCE_WIDTH`)**: 1920.0 dp
*   **参考高度 (`REFERENCE_HEIGHT`)**: 1080.0 dp
*   **基准字号 (`REFERENCE_FONT_SIZE`)**: 20.0 sp

所有的计算（位置、边距、字号）都以此为锚点进行。

---

## 2. 坐标与位置系统

### 相对坐标 (`RelativeOffset`)
字幕的位置不使用绝对像素，而是使用 `0.0` 到 `1.0` 的比例值。
*   `(0.5, 0.5)` 代表容器的中心。
*   渲染时，通过 `toOffset(containerSize)` 将比例转换为当前画布的实际像素坐标。
*   **优点**: 当容器大小改变时，字幕始终保持在画面的相对位置（如右下角或正中间）。

---

## 3. 三层缩放机制

实现方案中存在三种相互独立的缩放因子，它们共同决定了最终的视觉效果：

### 1. 字体与排版样式 —— 样式属性
*   **来源**: `CaptionStyle` 中的 `fontScale`, `letterSpacing`, `textStyle`。
*   **作用**: 控制文本的基础视觉表现。
*   **计算**:
    *   **字号**: `fontSize = 基准字号 * fontScale * 密度`
    *   **字间距**: 使用 `em` 单位（如 `letterSpacing.em`），确保间距随字号缩放比例同步变化。
    *   **样式**: 支持互斥的 `Normal`, `Bold`, `Italic`, `Underline` 状态。
*   **特点**: 这些属性只影响文字本身的渲染，不影响背景、边框的布局计算。这保证了排版细节的调整不会破坏整体布局。

### 2. 变换缩放 (`captionTransform.scale`) —— 布局缩放
*   **来源**: `CaptionTransform.scale`
*   **作用**: 对整个字幕块（文字 + 背景 + 边距）进行整体缩放。
*   **特点**: 类似图片缩放，会同步缩放背景边距和边框。通常用于用户在界面上通过拖拽手柄对整个组件进行放大缩小。

### 3. 预览缩放 (`previewScale`) —— 环境缩放
*   **来源**: 动态计算 `(当前容器宽度 / 密度) / REFERENCE_WIDTH`
*   **作用**: 解决窗口大小不等同于设计稿大小的问题。
*   **特点**: 
    *   当窗口只有 960dp 宽时，`previewScale` 为 0.5，此时画面中所有内容都会等比例缩小一倍，以完整模拟 1920 宽度的布局。
    *   **关键点**: 在导出时，如果分辨率是 1920x1080 且密度为 1.0，则 `previewScale` 恰好为 1.0，不会对画面产生额外影响。

---

## 4. 渲染流程 (`drawCaption`)

渲染函数是一个纯绘制逻辑，其步骤如下：

1.  **测量**: 使用 `CaptionStyle.toTextStyle()` 结合当前 `density` 测量文字尺寸。
2.  **计算中心点**: 将 `RelativeOffset` 转换为像素坐标。
3.  **应用变换 (`withTransform`)**:
    *   `translate`: 移动到目标中心点。
    *   `scale(previewScale)`: 应用环境预览缩放。
    *   `scale(captionTransform.scale)`: 应用用户自定义缩放。
    *   `translate(-width/2, -height/2)`: 将绘制原点移回左上角，确保 `RelativeOffset` 是块的中心。
4.  **绘制**: 依次绘制背景矩形、边框和文字。

---

## 5. 预览与导出的一致性

这是方案中最精妙的部分，通过操纵 **密度 (`Density`)** 来抹平差异：

### UI 预览时
*   **密度**: 系统默认密度（如 Retina 屏通常为 2.0）。
*   **逻辑**: 文字按系统密度渲染，`previewScale` 根据窗口宽度自动调整，确保你在小窗口里看到的比例是正确的。

### 导出时 (`ExportManager`)
*   **目标分辨率**: 如 `width = 3840`, `height = 2160` (4K)。
*   **动态密度**: `exportDensity = 3840 / 1920 = 2.0`。
*   **结果**:
    *   所有的 `dp` 值（边距、圆角）在 `toPx()` 时会自动翻倍。
    *   文字在测量时，因为 `density` 变大，会生成高分辨率的字形，避免拉伸模糊。
    *   `previewScale` 计算结果为 `(3840 / 2.0) / 1920 = 1.0`。
    *   **结论**: 导出的图像完全没有使用“插值拉伸”，而是原生的高清像素渲染，且比例与预览完全一致。

## 6. 文件结构

*   `Constants.kt`: 存放参考分辨率和基准参数。
*   `Caption.kt`: 定义 `CaptionStyle` 数据模型及其到 `TextStyle` 的转换。
*   `CaptionRender.kt`: 核心绘制逻辑，跨平台通用。
*   `CaptionView.kt`: UI 界面，处理用户交互、Sidebar 和 `SelectionBox` 手柄。
*   `ExportManager.kt`: 负责离线像素渲染与文件保存。
